# Подготовка к домену

Локальная подготовка выполнена 5 октября 2026. Публикация и изменение DNS не выполнялись.

## Уже подготовлено

- Основная русская страница `/` и английская `/en/`. Каждая содержит переведённый HTML до выполнения JavaScript.
- Общий исходник `pages/home.html`. `npm run build:pages` обновляет локальные `index.html` и `en/index.html`; локальный сервер читает шаблон при запросе страницы.
- Отдельные title, description, lang, alt и подписи формы. Старые метаданные про разработку только на Framer больше не перезаписывают основную страницу.
- Настоящие ссылки RU/EN, короткий переход, сохранение раздела, выбранного формата и черновика формы. Без JavaScript ссылки продолжают работать. При reduced motion и переключении с клавиатуры шторка не показывается.
- Взаимные `hreflang` ru/en/x-default. На локальной версии адреса относительные; production-сборка делает их абсолютными.
- Open Graph и Twitter Card, отдельные PNG 1200×630 для RU/EN. `scripts/make-social-images.ps1` позволяет пересобрать изображения на Windows.
- Генерация собственного canonical и og:url каждой страницы из SITE_URL. В локальной версии canonical и og:url намеренно отсутствуют.
- Sitemap с двумя основными URL создаётся только при явном включении индексации. Эксперименты v2/v3 исключены и получают noindex.
- По умолчанию robots.txt запрещает обход, а основные страницы содержат noindex. Это настройка превью, не готового публичного сайта.
- Страница 404 и корректный локальный HTTP 404; favicon уже был на сайте.
- Прямые ссылки Email, WhatsApp, Telegram присутствуют в исходном HTML и работают без JavaScript.
- Форма использует свой action, который можно задать при сборке через CONTACT_ENDPOINT. По умолчанию `/api/contact`.
- Уже существующий серверный обработчик проверяет входные данные, ограничивает частоту отправок и не сообщает об успехе без подтверждения Telegram. Токены остаются в серверных переменных окружения.
- Тесты RU/EN, внутренних ресурсов и якорей, метаданных для домена и вложенного пути, запрета случайной индексации, восстановления перехода; тесты отправки используют заглушку Telegram и не отправляют реальные сообщения.

## При переезде

1. Выбрать хостинг, подключить домен, DNS и HTTPS. Определить основной www/non-www адрес и редиректы.
2. Задать SITE_URL с конечным HTTPS-адресом и завершающим `/`. Для сайта в подкаталоге включить подкаталог. Не подставлять временный GitHub-адрес вместо будущего домена.
3. На хостинге запустить серверный обработчик формы и задать TELEGRAM_BOT_TOKEN / TELEGRAM_CHAT_ID. GitHub Pages не исполняет `contact-api.mjs`; размещение endpoint нужно решить отдельно. При другом origin потребуется явная серверная настройка CORS, сейчас локальный обработчик принимает только тот же origin.
4. Проверить реальную доставку, ошибку сервера, ограничение частоты и таймаут уже на выбранной инфраструктуре. До этого нельзя считать форму подключённой.
5. Подготовить документы по фактическим условиям деятельности и обработке данных. В футере ссылка «Политика конфиденциальности» пока без адреса; подключить её после подготовки документа.
6. Когда контент и форма готовы, включить SITE_INDEXABLE=true и собрать сайт. Это одновременно включает robots и генерирует sitemap. Без SITE_URL сборка отклонит включение индексации.
7. При публикации в корне собственного домена убрать GitHub-настройку SITE_BASE_PATH=/popovweb/ или задать `/`. Она нужна для ссылок на главную со страницы 404 при хостинге в подкаталоге.
8. Проверить реальные URL, HTTP-коды 404, редиректы, canonical, hreflang, og:url, og:image, robots.txt и sitemap.xml на хостинге. Убедиться, что в sitemap нет временного адреса и экспериментальных страниц.
9. Подтвердить домен в Google Search Console и Яндекс Вебмастере, отправить sitemap и проверить индексирование.
10. Проверить превью в Telegram, Core Web Vitals / Lighthouse, мобильные устройства и реальные внешние ссылки на production. Производительность локального сервера не является измерением production.

## Настройки сборки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| SITE_URL | не задана | Будущий публичный HTTPS-адрес для canonical, hreflang, OG и sitemap |
| SITE_INDEXABLE | false | Разрешать индексацию только после готовности к запуску |
| SITE_BASE_PATH | / | Путь до сайта для страницы 404; GitHub workflow задаёт /popovweb/ |
| CONTACT_ENDPOINT | /api/contact | Адрес серверного обработчика формы |

Переменные сборки задаются в окружении команды `npm run build`, например в настройках хостинга. Сборка не читает локальный `.env` с токеном бота и не копирует его в dist. Локальный `npm start` использует `.env` только на сервере.

Справка: [Google о языковых версиях](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites), [hreflang](https://developers.google.com/search/docs/specialty/international/localized-versions), [назначение robots.txt](https://developers.google.com/search/docs/crawling-indexing/robots/intro).
